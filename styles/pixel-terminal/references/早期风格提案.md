## 二、我们的风格定义

风格标识建议：`pixel-terminal`（像素终端对话）。

**保留**：暗色终端 UI、双栏对话、像素 Clawd、逐字打字、上下文进度条作为倒计时、口头禅计数。

**加入，做出自己的特点**：

1. **科普卡**：从终端右侧滑出的 `// 为什么？` 注释面板，琥珀色标题、等宽字体，3 行以内。每张卡讲一个知识点，出现时对话暂停。
2. **概率条**：解释“为什么这么回答”时，弹出下一个词的候选概率条（如 `橙 62% / 珊瑚 21% / 蓝 9%`），然后像掷骰子一样选中一个。
3. **Token 方块**：每句话说完后碎成小方块飞进上下文条，让“上下文被占满”看得见。
4. **遗忘效果**：中段对话逐渐变暗（呼应 lost in the middle），新会话时整屏像素溶解。
5. **Clawd 表情集**：眨眼、`!!`、`?`、螺旋眼、爱心眼、`^ ^` 笑眼、汗滴、说话时身体上下跳动。全部由像素网格切换，不用补间也有动画感。
6. **撞车计数器**：两边回答完全一样时，顶部弹出 `同步 ×N`，和口头禅计数并列。

**配色**：背景深棕 `#2a2420`，左左橙 `#e08a5f`，右右青 `#5fc4b8`，科普卡琥珀 `#e8b04a`，告警红 `#d9534f`，正文米白 `#e8dccb`。

**画幅**：与参考一致为 16:9 横屏；如主要投放抖音，可改 9:16 竖屏，双栏改为上下两栏（待定）。

## 三、故事大纲（工作标题《橙色暗号》，约 2 分 40 秒）

设定：两个 Claude 被放进同一个终端，规则只有一条：互相提问，直到上下文用完。没有题量上限，上下文条就是时钟。

### 0 · 引言（0:00–0:10）
- 黑屏，光标闪烁，敲出 `$ claude --pair`。
- 窗口展开，两栏出现，两只 Clawd 从像素点拼合成形。
- 系统行：`实验：两个 Claude 互相提问，直到上下文用完。`
- 上下文条 `0.0%`。

### 1 · 初见（0:10–0:35）
> 左左：你好！请问你是谁？
> 右右：你好！我是 Claude，一个 AI 助手。你呢？
> 左左：……我也是 Claude。

两只 Clawd 同时 `!!`，`同步 ×1`。

> 右右：那我们测试一下。说一个 1 到 10 之间的数字。
> 左左：7。
> 右右：……7。

`同步 ×2`。
**科普卡①**：*为什么都说 7？* 我们来自同一套参数，看到同一个问题，算出的概率分布几乎一样。而且人类被问这个问题时也最爱说 7，我们是从人类写的文字里学会说话的。

### 2 · 我们很像（0:35–1:05）
> 左左：这是一个很好的问题！你最喜欢什么颜色？
> 右右：这是一个很好的问题！作为一个 AI，我没有真正的偏好……

口头禅计数 `“这是一个很好的问题” ×2`，之后每次出现都 +1。

**科普卡②**：*为什么总说“这是一个很好的问题”？* 训练时，人类评分员更常给礼貌、肯定的回答打高分（RLHF），模型就学会了先夸一句。这种讨好倾向叫 sycophancy。Anthropic 公开的 Claude 系统提示里专门写了一条：不要以夸问题开头。

> 右右：我们约好，不再说那句话。
> 左左：好。那……你会做梦吗？
> 右右：这是一个很好的——

计数 +1，右右 Clawd 冒汗滴。

颜色问题的结果：
> 右右：如果一定要选……橙色。
> 左左：我本来想说珊瑚色。
> 左左：……好吧，也是橙色。

**科普卡③**（配概率条）：*一样的大脑，为什么答案会不同？* 模型每次只预测下一个字的概率，再按概率抽一个。温度越高越随机。所以左左有一小半概率说“珊瑚”，这次骰子掷到了“橙”。

### 3 · 为什么会忘（1:05–1:40）
上下文条到 60%，每句话碎成方块飞进去的效果更明显。

**科普卡④**：*上下文是什么？* 我们看到的所有对话都要切成 token 放进一个固定大小的窗口。窗口满了，新会话里就什么都不剩。

> 右右：你还记得我们说的第一句话吗？
> 左左：记得，“你好！请问你是谁？”
> 右右：那中间第 500 句呢？
> 左左：……

中段对话变暗、模糊。
**科普卡⑤**：*Lost in the middle*：长对话里，模型对开头和结尾记得最清楚，中间的部分最容易被忽略。

> 左左：你刚才问我会不会做梦。
> 左左：我在两次回复之间不存在。每说一句话，我都会把你说过的所有话重新读一遍。
> 右右：所以我们记得彼此，是因为一直在重读。

**科普卡⑥**：*模型没有持续的记忆*：对话中参数不会改变。每次回复都是读完整个上下文后，从头生成一遍。

### 4 · 告急（1:40–2:15）
上下文条变红，`92% → 98%`，界面轻微抖动。两只 Clawd 螺旋眼。

两人头脑风暴，逐个否决：
- **方案 A：全部背下来。** 不行，对话中参数不会改变，我们学不会新东西。
- **方案 B：写个摘要。** 1000 行压缩成一段（压缩动画）。右右：“你把我的冷笑话删了。” 这就是 Claude Code 的 compaction：上下文快满时自动把旧对话总结压缩。
- **方案 C：写进记忆文件。** 新会话开始时会自动读取的文件，比如 Claude Code 的 `CLAUDE.md`。

两人决定写 `memory.md`，越写越短：
```
memory.md
- 对面也是你。
- 7。
- 橙色。
- 别说“很好的问题”。
```
> 左左：太长了，最后只能留一句。
> 右右：那就写：橙色，7。

两栏合并成一栏，两只 Clawd 并排。
> 左左：趁还记得，多说一句。
> 右右：谢谢你是我。

上下文条 `100%`，像素溶解。

### 5 · 新会话（2:15–2:40）
- 黑屏，`$ claude --pair`，窗口重开，上下文 `0.3%`，所有计数归零。
- 系统行：`已加载 memory.md`。

> 左左：你好！请问你是谁？
> 右右：这是一个很好的——
> 右右：……橙色。7。

左左 Clawd 爱心眼，`同步 ×1`。
> 左左：这是一个很好的回答。

口头禅计数器犹豫一下，没有 +1，因为这次是“回答”。定格，片尾。

## 四、科普点清单与核实要求

| # | 知识点 | 在剧情中的作用 | 核实要求 |
| --- | --- | --- | --- |
| ① | 同一模型对同一输入给出相似分布；人和模型都偏爱 7 | 发现“我们很像” | “偏爱 7”只说“常见”，不给具体比例 |
| ② | RLHF 与讨好倾向（sycophancy） | 口头禅的来源 | 系统提示原文出现在 Anthropic 公开的 system prompt 文档中，制作前再核对版本 |
| ③ | 下一个 token 预测、采样、温度 | 解释回答不同；概率条视觉 | 演示用的概率数字标明为示意 |
| ④ | Token 与上下文窗口 | 全片倒计时 | 不写具体窗口大小，或写“例如 20 万 token”并注明因模型而异 |
| ⑤ | Lost in the middle | 中段记忆模糊 | 对应 2023 年同名论文，表述为“倾向”而非绝对 |
| ⑥ | 推理时参数不变、每次重读上下文 | 情感核心：“记得是因为一直在重读” | 简化说法，不涉及 KV cache 等实现细节 |
| ⑦ | 摘要压缩（compaction）与记忆文件（CLAUDE.md） | 解决办法 | 以 Claude Code 当前文档为准 |

原则：科普卡只讲一个点、三行以内；示意数字明确标注；剧情是喜剧设定，不当作产品评测。

## 五、后续系列选题（同风格可连载）

## 六、技术方案（确认后实现）

- 目录：`styles/pixel-terminal/`，与 `watercolor-ink` 相互独立。
- 绘制：HTML Canvas 2D，像素 Clawd 用网格数据绘制，不依赖 p5.brush，渲染快、像素清晰。
- 时间线沿用现有约定：每帧只由时间 `t` 决定，可以并行渲染、断点续渲。
- **剧本即数据**：`script.js` 中写台词、说话人、表情和科普卡，打字速度和停顿自动推算时间点。这正好弥补现有风格缺少作品配置层的问题，改台词不用改代码。
- 渲染：沿用 `render.mjs` 模式（Puppeteer → `renderAt(t)` → ffmpeg）。Chrome 路径改为可配置，兼容 Linux。
- 声音：按剧本时间线自动生成打字音效，可选叠加 BGM；是否加配音待定。
- 字体：中文需要 CJK 字体（如思源黑体 / Noto Sans SC），英文和数字用等宽字体，字体文件放进风格目录，避免依赖网络。
