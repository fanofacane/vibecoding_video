# 情景喜剧群聊风 · 制作规范

本文件定义 `sitcom-flat` 风格：画面怎么画、剧本怎么写、怎么卡音乐。新作品照着它做，就能和《AI 甄嬛传》第一集保持同一个风格。

## 1. 风格定位

把一群 AI（或任何品牌、产品）拟人成情景喜剧里的角色。用户在群聊里提一个简单请求，每个角色按自己的人设给出离谱回应，最后由一个角色干脆利落地解决，再接一个反转收尾。

画面参照《爱情公寓》式青春情景喜剧片头：扁平卡通、蓝天白云、樱花、粗体粉色标题、“角色名 / 演员（饰）”式的人物介绍，正片是手机群聊界面。全片配一首歌，转场卡在歌词句首。

适合：AI 产品群像、品牌拟人吐槽、职场/合租/宫斗等群像段子。时长 60–120 秒。

## 2. 每集结构

| 段落 | 时长 | 内容 |
| --- | --- | --- |
| 片头 | 前奏内，`0 → P(0)` | 屋顶线条自绘并以爱心收尾 → 标题逐字弹出 → 全体角色 Logo 逐个弹出并标注身份；全部在人声进入前一拍完成 |
| 提出任务 | 2 句 | 第一段群聊，开头显示集名横幅；用户抛出任务（可附文件卡片），全员接单 |
| 角色段 × N | 每个角色 1 + 2～3 句 | 介绍卡（1 句）→ 群聊（2～3 句）。每个角色只演一个性格点 |
| 收尾角色 | 1 + 3 句 | 最后出场的角色一步解决问题，最好利用前面别人留下的东西做伏笔 |
| 结尾反转 | 2 句 | 某个角色再犯一次自己的毛病，用户怒吼，毒舌角色补刀 |
| 片尾 | 剩余时间 | 标题 + 免责声明（不放下集预告） |

“句”指一句歌词，约 2 小节；在 `work.js` 中用 `P(n)` 表示第 n 句的开始时间。

## 3. 视觉规范

**画布**：1920 × 1080，30 fps。每帧只由时间决定，不依赖上一帧，不用 `Math.random()`（用 `hash(i)`）。

**配色**（`src/engine.js` 中的 `C`）

| 用途 | 色值 |
| --- | --- |
| 天空渐变 | `#5BAEF0` → `#D8EDFC` |
| 标题粉 / 标题暗部 | `#F2558C` / `#BE2C68` |
| 樱花 | `#F8A9C4` → `#EE7FA6` |
| 正文墨色 / 次要灰 | `#1E1E24` / `#8A8F99` |
| 用户气泡蓝 | `#2F6BFF` |
| 打码与警示红 | `#E8453C` |
| 角色色 | 品牌主色；介绍卡背景为品牌色与白混合 62%～88%，群聊背景混合 84%～94% |

**字体**：Noto Sans SC，标题与大字 900，正文气泡 800，系统提示 500。

| 元素 | 字号 |
| --- | --- |
| 片头标题 | 190 px，白边 + 暗部厚度 |
| 集名横幅、拟声大字 | 110～180 px |
| 介绍卡标签大字 | 150 px |
| 介绍卡身份 / 演员（饰） | 78 px / 40 px |
| 群聊气泡正文 | 58 px，行高 76 px，单行最宽 1180 px |
| 群聊名字、顶栏标题 | 30 px / 44 px |

**角色**：只用品牌 Logo 本体，不加五官、头饰或服装。介绍卡上大 Logo 400 px、小 Logo 120 px，群聊头像 116 px 白色圆底。目前可用的 Logo：Claude、ChatGPT、Gemini、Grok、DeepSeek、豆包；新增 Logo 的方法见第 7 节。

**动效**

| 动作 | 时长与曲线 |
| --- | --- |
| 弹出（标题字、Logo、气泡、头像） | 0.22～0.35 s，`backOut` 回弹 |
| 名条、标签条滑入 | 0.3 s，`easeOut` |
| 标签逐字打出 | 每字 0.14 s |
| “正在输入” | 默认 0.7 s，可按人设改（例如深度思考 2 s） |
| 群聊滚动 | 0.35 s 缓动 |
| 拟声大字 | 弹出 0.22 s，抖动后 1.4 s 内淡出 |
| 节拍律动 | 介绍卡大 Logo、片头 Logo 每拍轻微上跳；片头鼓点过门时 Logo 跳起 |

## 4. 剧本写作

1. **一个角色一个梗。** 介绍卡上的标签（2～6 字）就是这个梗，群聊只演它：例如“你说得对”的角色每句都以“你说得对”开头。
2. **用户的请求要简单具体**，全集只有一个任务（例如改一个错别字），每个角色都在同一件事上翻车。
3. **每段 3～7 条消息**，结构为：请求 → 符合人设的离谱回应 → 用户追问 → 重复或升级 → 落点（拟声字、计数胶囊或用户的反应）。
4. **长度**：每条消息不超过 30 字。下一条消息至少间隔“字数 ÷ 6 + 0.5”秒，留出阅读时间。
5. **收尾角色**：话少、一步办成，最好引用前面留下的东西（被圈出的错字、被扔掉的原稿）；再加一句体贴的话，体现“懂你”。
6. **结尾**：让某个角色把自己的毛病再犯一次，用户一句怒吼，毒舌角色补刀。
7. **标记**：`{高亮}` 用说话人的品牌色；`[脏话]` 打码成黑底红字，并配“哔——”拟声字；`kind: 'note'` 做灰色系统提示；`kind: 'doc'` 做文件卡片（可圈字、改字、盖章）。
8. 片尾写“纯属虚构，博君一笑”之类的免责声明；台词是喜剧夸张，不能写成产品评测或真实数据。

## 5. 配乐与卡点

1. 运行 `python3 tools/analyze_music.py <歌曲或视频> --extract works/<id>/assets/music.m4a --spec out/spec.png`。它会：
   - 测出节拍长度 `beat`（在整首歌上拟合）；
   - 找到人声进入点 `vocals`：优先取前奏鼓点过门后的第一拍，并列出其他候选；
   - 找到过门鼓点 `fill`，片头 Logo 会在这几下跳起；
   - 找到歌曲结束点 `end`，截掉之后的平台水印语音和静音；
   - 导出截好、带 0.5 秒淡出的配乐。
2. 把输出的数值粘进 `work.js` 的 `music`。**自动判断可能差一拍**：用耳朵或频谱图确认人声进入点，进入点前片头必须已经完成。
3. 时间线规则：
   - 片头放在 `[0, P(0)]`，人声一进立即切到第一段群聊；
   - 所有转场落在句首 `P(n)`；
   - 群聊消息、计数和拟声字的时间会自动吸附到节拍；
   - 片尾在 `music.end` 结束。
4. 配乐通常来自他人的作品：`works/*/assets/music.*` 已加入 `.gitignore`，不提交仓库。

## 6. 制作流程

1. 复制 `works/_template/` 为 `works/<作品id>/`，写好角色表和每段台词。
2. 处理配乐（第 5 节），填好 `music`，按句数排好 `timeline`。
3. 打开 `index.html?work=<作品id>` 拖动时间条预览，或渲染关键帧拼图：
   `node render.mjs --work=<作品id> --sheet=3,8,15,20`
4. 检查：
   - 片头是否在人声前完成；
   - 每段最后一条消息是否有足够阅读时间；
   - 气泡是否被顶栏或计数胶囊遮挡。
5. 出成片：`node render.mjs --work=<作品id>`，输出到 `out/<作品id>/<作品id>.mp4`。

## 7. 代码结构与扩展

| 文件 | 内容 |
| --- | --- |
| `src/engine.js` | 画布、缓动、配色、天空、云、樱花、城市、Logo、粗体字、计数胶囊 |
| `src/logos.js` | Logo 矢量路径 |
| `src/chat.js` | 群聊：消息排版与换行（标点不出现在行首、行宽均衡）、头像、“正在输入”、自动滚动、文件卡片、印章、拟声字 |
| `src/components.js` | 节拍网格 `P / onBeat / snap`、片头 `opening`、介绍卡 `card`、群聊段 `chat`、集名横幅、片尾 `endCard` |
| `src/runtime.js` | 按 `?work=` 加载作品、预加载字形、提供渲染接口 |
| `works/<id>/work.js` | 作品：标题、配乐参数、角色、台词、时间线 |

- **新增 Logo**：从开源图标包 `@lobehub/icons-static-svg` 取 SVG，把路径和颜色按现有格式加进 `src/logos.js`，用新的 key 在 `cast` 中引用。
- **新增镜头类型**：写成 `(t, lt) => { ... }` 的函数（t 为全片时间，lt 为本镜头内时间），必须画满整帧；通用的放进 `src/components.js`，只属于某个作品的写在该作品的 `work.js` 里。
